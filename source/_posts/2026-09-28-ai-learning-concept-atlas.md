# 做了一个 99 概念的 AI 知识图鉴：纯静态站的架构与间隔重复设计

学 AI 这一年多，我最大的困扰不是"找不到资料"，而是**概念又多又碎、看一遍忘一遍**：RAG、Function Calling、CoT、Agent Memory……每个都"好像懂了"，面试里被追问一层就露馅。

所以我给自己做了一个学习网站 [AI_learning](https://github.com/ChenYi1031/AI_learning)（[在线地址](https://chenyi1031.github.io/AI_learning/)）：把 AI / Agent 相关的 99 个核心概念做成卡片图鉴，配论文精读和实战项目教程，内置间隔重复自测和跨设备云同步。这篇讲它的设计和实现。

## 内容设计：99 概念 × 9 层

内容结构比技术实现更重要。每个概念固定 9 层：

1. 是什么
2. 出现的背景
3. 解决什么问题
4. 一个类比
5. 要点
6. 常见误区
7. 应用场景
8. 代码实例
9. 延伸阅读

"类比"和"误区"这两层是我刻意加的：类比是检验自己是否真懂的最快方式，误区则是实际学习中最贵的信息（踩过的坑才写得出）。概念之间互相跳转，比如从 Function Calling 跳到 MCP 再跳到 Agent Memory，**知识的连接方式本身就是内容**。

除此之外还有：6 个实战项目（智能客服、LLM 网关、日报 Agent、多 Agent 流水线、秒杀系统、CI/CD 流水线，各配架构图与事故复盘）、《Attention Is All You Need》逐节小白串讲。

## 纯静态、零依赖的取舍

技术上这个站是"反向内卷"的：不用框架、不用构建工具，原生 JS SPA，所有内容是 JSON 数据文件。

这样选的理由：

- **内容站的生命周期以年计**，框架会过时，原生 JS 不会；零构建意味着数据文件改完即生效
- 部署到 GitHub Pages 就是纯静态托管，免费、稳定、无需运维
- 搜索、筛选、跳转这些交互的复杂度，原生 JS 完全 hold 得住，为它们引入框架不值

代价是状态管理全靠手写，但这个站的状态其实很简单（当前概念、复习队列、同步队列），手写反而清晰。

## 间隔重复：Leitner 盒子

防止遗忘的核心是**主动回忆 + 间隔重复**。实现选了 Leitner 盒子系统，比 SM-2 简单得多但完全够用：

- 5 个盒子，间隔分别为 1 / 3 / 7 / 14 / 30 天
- 自测时先看问题主动回忆，再翻答案自评：答对进下一盒，答错回第一盒
- 复习队列 = 所有"到期"的卡片，按盒子优先级排序

```javascript
function nextReview(card, correct) {
  const box = correct ? Math.min(card.box + 1, BOXES.length - 1) : 0;
  return { ...card, box, due: Date.now() + BOXES[box].interval * DAY };
}
```

配套的学习统计：近 12 周复习热力图、分类掌握度（按概念分类聚合盒子分布）、连续打卡天数。数据可视化本身也成了坚持的动力——热力图断一天真的很难受。

## 云同步：localStorage 乐观写入 + Turso

进度只存浏览器是不够的（换设备就清零），所以加了云同步。但主站部署在 GitHub Pages——**没有后端**。方案是把同步 API 放在 EdgeOne Pages 的 Node Function 上，数据库用 Turso（libSQL）：

```
浏览器（纯静态）                EdgeOne Pages              Turso (libSQL)
┌──────────────────┐  fetch  ┌──────────────────┐ HTTP  ┌──────────────┐
│ localStorage      │◀──────▶│ api/progress.js  │──────▶│ review_events│
│ 离线缓存+乐观写入  │ /api/  │ (token 在环境变量) │       │              │
└──────────────────┘ progress └──────────────────┘       └──────────────┘
```

几个关键设计：

- **乐观写入**：复习记录先写 localStorage，立即返回；同步引擎后台批量上传，失败自动重试
- **离线补传**：断网时的记录暂存队列，恢复后自动补传，不丢数据
- **LWW 合并**：导入/同步冲突按时间戳最后写入胜出，学习数据没有真正意义上的"并发编辑"，LWW 足够
- **凭证安全**：数据库 token 在 Node Function 环境变量里，前端永远接触不到

## 双平台部署的真实取舍

这是个真实的踩坑记录：GitHub Pages 是主站（稳定、永久链接），但 Node Function 只随 EdgeOne Pages 部署——所以主站上同步徽章显示"离线模式"（进度仅存本机，功能不受影响），完整同步链路要走 EdgeOne，而 EdgeOne 默认域名对大陆网络有访问限制，正式启用需要绑定自定义域名。

最后的策略是**接受双平台的差异**：核心学习功能全离线可用，云同步作为增强能力存在。这也再次验证了做 FitFlow 时的结论：纯前端 + 本地存储的应用，"降级体验"应该是设计出来而不是碰到的。

## 小结

这个项目技术密度不高，但**内容密度极高**——99 个概念的 9 层内容全部要自己写、自己验证。最大的收获反而是：整理这套概念卡的过程，比任何一遍看教程都更能暴露理解的漏洞。写不出"类比"层的概念，就是没真懂的概念。
